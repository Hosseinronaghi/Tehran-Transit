# نقشهٔ آفلاین، برنامهٔ حرکت و انتشار Android

## دریافت نقشه

در «تنظیمات → نقشهٔ آفلاین»، دکمهٔ دانلود برای بستهٔ شناخته‌شدهٔ `2026-Q4-r3` بدون بررسی جداگانه کار می‌کند. بررسی دستی یا تناوبی نسخه‌های تازه را پیدا می‌کند. بررسی تناوبی هنگام بازکردن برنامه یا بازگشت به آن انجام می‌شود و چهار حالت هفتگی، ماهانه، فصلی یا خاموش دارد. دریافت بسته تأیید جداگانه می‌خواهد.

- برنامه مسیر دانلود مستقیم GitHub و مسیر جداگانهٔ GitHub Releases API را امتحان می‌کند.
- روی دستگاه بدون دسترسی به این دو نشانی می‌توان فایل `.mbtiles` معتبر را مستقیم از حافظهٔ دستگاه وارد کرد. اعتبار فایل از طریق SHA-256 ثبت‌شده در برنامه یا فهرست دریافت‌شده بررسی می‌شود.
- منبع مستقل HTTPS را می‌توان در تنظیمات وارد کرد یا با متغیر مخزن `RAHA_MAP_MIRROR_URL` در APK قرار داد. مسیر فایل در فهرستِ آینه باید روی دامنهٔ در دسترس همان کاربران باشد. `RAHA_MAP_MANIFEST_URL` برای جایگزین‌کردن نشانی اصلی است.
- برای آینه، همان فایل و SHA-256 انتشار را روی سرور قرار دهید. فیلدهای فهرست `edition`، `format` با مقدار `raster_mbtiles`، `url`، `sha256`، `bytes`، `minzoom` و `maxzoom` هستند. فیلد اختیاری `mirrors` فهرست نشانی‌های HTTPS فایل است.
- سرورهای دارای پشتیبانی `Range` امکان ادامهٔ دریافت را می‌دهند. فایل پس از بررسی حجم، هش و SQLite فعال می‌شود. نسخهٔ قبلی تا پس از نصب موفق حفظ می‌شود.
- بستهٔ فعلی از دادهٔ خام OSM/Geofabrik تولید شده و زوم ۹ تا ۱۵ را دارد. برای نسخه‌های بعدی انتساب و شرایط ODbL در فهرست و فایل بسته حفظ شوند.

## زمان‌بندی آفلاین اتوبوس و BRT

در «جزئیات ایستگاه → زمان رسیدن، حرکت و ثبت دستی» می‌توان خط، جهت، روزهای هفته، ساعت رسیدن یا حرکت، منبع و یادداشت را ثبت، ویرایش یا حذف کرد. داده در یک دیتابیس محلی مستقل از دیتابیس همراه APK می‌ماند.

برای ورود دادهٔ دارای مجوز، در تنظیمات فایل JSON با `schema: 1` را انتخاب کنید. هر ردیف این فیلدها را دارد:

| فیلد | مقدار |
|---|---|
| `stop` | شناسهٔ رکورد ایستگاه از `tehran_bus_stations.json` با پیشوند `bus:` |
| `service` | شمارهٔ خط با پیشوند `bus:` یا `brt:` مطابق دادهٔ برنامه |
| `direction` | `outbound`، `inbound` یا `unknown` |
| `days` | ماسک روزها، شنبه ۱، یکشنبه ۲، دوشنبه ۴، سه‌شنبه ۸، چهارشنبه ۱۶، پنجشنبه ۳۲ و جمعه ۶۴. مجموع همهٔ روزها ۱۲۷ است |
| `arrival`، `departure` | یکی یا هر دو با قالب `HH:mm` و به وقت محلی تهران |
| `source` | نام یا پیوند منبع و تاریخ یا نسخهٔ انتشار |
| `notes` | توضیح اختیاری، مانند شرایط تعطیلات |

آغازگر `assets/data/timetable.json` عمداً بدون ردیف است. کد عمومی بررسی‌شده برنامهٔ حرکت را از سرویس داخلی می‌گیرد و هیچ ردیف برنامهٔ حرکت دارای مجوز بازنشر از آن تأیید نشد. دادهٔ منتشرشده در آینده باید همراه با مجوز و تاریخ اعتبار وارد شود. اطلاعات زمان‌بندی، برنامهٔ حرکت یا مشاهدهٔ دستی را نشان می‌دهد.

## ساخت و انتشار APK

از Flutter `3.50.1` و Java 21 استفاده کنید. Android SDK، Build Tools و NDK مندرج در پروژهٔ Android برای ساخت لازم‌اند. گردش‌کار Android APK همین مراحل را اجرا می‌کند.

```bash
python3 scripts/build_database.py assets/data/tehran_bus_stations.json assets/data/transit.sqlite
python3 scripts/validate_assets.py assets/data/transit.sqlite assets/data/rail_brt.geojson
flutter pub get --enforce-lockfile
flutter analyze --no-fatal-infos
flutter test
flutter build apk --release
```

ساخت‌های عادی Pull Request و `main` خروجی پیش‌نمایش تولید می‌کنند. انتشار پایدار از اجرای دستی Build Android APK روی `main` با گزینهٔ `publish` انجام می‌شود. کلید Android باید همان کلیدی باشد که برای به‌روزرسانی‌های قبلی استفاده شده، اگر چنین کلیدی وجود دارد. چهار Secret زیر برای انتشار لازم‌اند.

- `RAHA_KEYSTORE_B64`
- `RAHA_STORE_PASSWORD`
- `RAHA_KEY_ALIAS`
- `RAHA_KEY_PASSWORD`

اثر انگشت SHA-256 گواهی انتشار را در متغیر مخزن `RAHA_SIGNING_SHA256` قرار دهید. CI شناسهٔ `org.tehrantransit.tehran_transit`، نسخه، گواهی و افزایش شمارهٔ ساخت را بررسی می‌کند. انتشارهای جدید با برچسبی مانند `v0.6.3+10` ثبت می‌شوند. نسخه‌های قبلی دارای گواهی متفاوت، ارتقای مستقیم اندروید را نمی‌پذیرند. برای نصب مجدد می‌توان فایل رسمی نقشه را از حافظه وارد کرد. داده‌های موجود روی دستگاه پیش از حذف نسخهٔ قبلی باید جداگانه پشتیبان‌گیری شوند.
