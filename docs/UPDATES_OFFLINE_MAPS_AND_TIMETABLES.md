# رها تهران — آپدیت نصب‌شده، نقشه اختیاری و زمان‌بندی اتوبوس

## ۱. به‌روزرسانی روی APKهای قبلی

شناسه اپ را ثابت نگه دارید: `org.tehrantransit.tehran_transit`. هر انتشار باید `versionCode` بالاتر داشته باشد (در Flutter از عدد پس از `+` در `pubspec.yaml`).

**یک مانع تأییدشده:** APKهای قبلی آزمایشی در CI با کلید موقت دیباگ ساخته شده‌اند. امضاهای نسخه‌های v0.4 و v0.5 با هم متفاوت‌اند؛ اندروید آن‌ها را مستقیم روی هم نصب نمی‌کند. صرف حفظ نام و شناسه یا افزایش شماره نسخه این مشکل را حل نمی‌کند. برای آپدیت این نسخه‌ها، تنها راه دسترسی به **کلید خصوصی همان امضا** است. کلید عمومی یا گواهی داخل APK برای بازسازی کلید کافی نیست. برای کاربران این نسخه‌ها ممکن است یک بار حذف و نصب مجدد لازم شود (پیش از حذف، اطلاعات شخصی مهم باید پشتیبان‌گیری شود). ما به‌هیچ‌وجه قول سازگاری با این امضاهای قدیمی نمی‌دهیم.

### فعال‌سازی امضای ثابت برای نسخه‌های آینده

بهتر است مالک پروژه یک کلید امضای مستقلِ بلندمدت بسازد و آن را **فقط در محل امن و GitHub Actions Secrets** نگه دارد؛ هرگز داخل مخزن عمومی ثبت نکنید. برای نمونه در کامپیوتر خودتان:

```bash
keytool -genkeypair -v -keystore raha-release.jks -alias raha-release \
  -keyalg RSA -keysize 3072 -validity 10000
# base64 خروجی را با ابزار سیستم‌عامل خود به یک رشته بدون شکست خط تبدیل کنید.
```

در GitHub → Settings → Secrets and variables → Actions → Repository secrets چهار کلید تنظیم شود:

- `RAHA_KEYSTORE_B64`: محتوای Base64 فایل `raha-release.jks`
- `RAHA_STORE_PASSWORD`: رمز نگه‌دارنده
- `RAHA_KEY_ALIAS`: `raha-release`
- `RAHA_KEY_PASSWORD`: رمز کلید

گردش‌کار `scripts/configure_android_signing.py` فقط با حضور هر چهار مقدار از امضای ثابت استفاده می‌کند؛ در نبود آن‌ها یک **APK پیش‌نمایش با امضای ناپایدار** تولید می‌شود و `APP_SIGNING.txt` در خروجی درباره عدم امکان آپدیت مستقیم هشدار می‌دهد. کلید را جداگانه پشتیبان‌گیری امن و خارج از GitHub کنید؛ گم‌کردن آن مسیر آپدیت‌های آینده را از بین می‌برد.

**مهاجرت:** داشتن نام جدید «رها تهران» به‌تنهایی امضا را عوض نمی‌کند، اما پیش‌نمایش‌های سابق دارای کلیدهای متفاوت بوده‌اند. پس از راه‌اندازی کلید ثابت، تمام انتشارهای بعدی با همان کلید، شناسه برنامه و نسخه افزایشی قابل آپدیت خواهند بود.

## ۲. نقشه آفلاین اختیاری، کم‌حجم و قابل به‌روزرسانی فصلی

- **APK سبک باقی می‌ماند** و داده ایستگاه‌ها/خطوط/مسیریابی همچنان بدون اینترنت کار می‌کنند.
- برای کامل‌شدن خیابان‌ها و نام مکان‌ها در حالت آفلاین، کاربر از صفحه «تنظیمات → نقشه کامل تهران بدون اینترنت» به صورت **اختیاری** بسته را دانلود می‌کند. پیش از آن زمینه نقشه آنلاین است.
- آرشیو منتخب: **رستری MBTiles** شامل کاشی‌های مجاز `png/jpg/webp`. این سازوکار عمداً با `flutter_map 7` سازگار است. بسته **PMTiles برداری** را نمی‌توان با این نمایشگر رستری استفاده کرد؛ اگر بعداً به فایل برداری سبک‌تر مهاجرت شود، به موتور نقشه و style/font محلی دیگری نیاز خواهد بود.
- بارگیری فقط پس از لمس دکمه و سپس اعتبارسنجی **HTTPS، SHA-256، SQLite و وجود کاشی** است. فایل ناقص موقت حذف می‌شود. پس از موفقیت جایگزین بسته قبلی می‌شود.
- برای اطلاع از نسخه جدید، کاربر دکمه «بررسی نسخه جدید نقشه» را می‌زند. «یادآوری فصلی» پس از گذشت ۹۰ روز، فقط داخل تنظیمات پیام می‌دهد. هیچ دانلود خودکار یا داده زنده پنهانی انجام نمی‌شود.
- نگه‌داری بسته به صورت مستقل از دیتابیس خطوط/ایستگاه‌ها در فضای داده اپ است. حذف نقشه آفلاین به مسیرهای ترانزیت آسیبی نمی‌زند.

### انتشار مستقل نقشه بدون ساخت APK تازه

یک فایل JSON عمومی و پایدار روی HTTPS متعلق به پروژه میزبانی کنید. قالب نمونه (لینک نمونه برای توضیح است و فعال نیست):

```json
{
  "edition": "2026-Q4",
  "format": "raster_mbtiles",
  "url": "https://maps.example.com/tehran-2026-q4.mbtiles",
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "bytes": 200000000
}
```

مسیر واقعی این manifest را به عنوان **GitHub Actions Repository Variable** به نام `RAHA_MAP_MANIFEST_URL` تنظیم و اپ را یک بار با آن بسازید. پس از آن فقط محتوای JSON را فصلی به نسخه جدید آپدیت کنید، بدون انتشار APK تازه. `sha256` باید هش واقعی باینری باشد؛ مقدار نمونه بالا برای استفاده واقعی مناسب نیست.

در وضعیت فعلی، **هیچ بسته واقعی و بررسی‌شده نقشه تهران به این پروژه اضافه نشده** و به همین دلیل گزینه دانلود تا آماده‌شدن فایل رسمی غیرفعال خواهد بود؛ نمایش این عدم آمادگی صادقانه است.

از `tile.openstreetmap.org` یا سرور برداری عمومی OSM نباید انبوه کاشی برای ذخیره آفلاین برداشت. استفاده از داده خام OSM/Geofabrik و تولید مستقل تحت شرایط مجوز یا ارائه‌دهنده مجاز لازم است. حقوق داده ODbL، اعتبارسنجی محدوده تهران، توضیح تغییرات نقشه، برچسب‌های فارسی و نگه‌داری آخرین نسخه سالم باید رعایت شود.

## ۳. ارقام خطوط فارسی و تنظیمات

- شماره خط مترو، BRT و اتوبوس با ارقام **۰۱۲۳۴۵۶۷۸۹** نمایش داده می‌شود؛ جست‌وجو با هر سه شکل رقم فارسی، عربی و لاتین ممکن است.
- تنظیمات فعلی: ظاهر روشن/تاریک/سیستم با ذخیره انتخاب، وضعیت نقشه آفلاین، بررسی دستی نسخه، دانلود/لغو/حذف در صورت انتشار بسته و یادآوری فصلی.
- فونت برنامه همان **Vazir** باقی می‌ماند.

## ۴. پنل بازشونده ساعت‌های حرکت از ایستگاه

در پنل جزئیات ایستگاه اتوبوس و BRT، بخش بازشونده «ساعت‌های حرکت و رسیدن اتوبوس» خطوط عبوری را به‌صورت فارسی نشان می‌دهد. **داده زمانی معتبر هنوز به پروژه متصل نیست**؛ در نتیجه برای هر خط «در دسترس نیست» نمایش داده می‌شود. نسخه بعدی فقط با منبع رسمی/مجاز و تعریف واضح *برنامه حرکت* در برابر *زمان تخمینی زنده* باید داده واقعی نشان دهد. زمان حدسی ممنوع است.
